feat(M1): 加 GitHub Contents API 数据源，绕开被封的 raw 域名

背景：你手机上报「四个源全部失败」，错误里是 raw.githack.com 域名解析失败。
我这边实测 jsDelivr 能正常拉到数据，所以是你网络访问不到 githubusercontent 系域名。

关键观察：你手机能解析 github.com（20.205.243.166），而 api.github.com
是**另一个域名**，往往同样可达。所以我加了一条完全不碰 raw 域名的通路。

改动：
- data_sync.dart 引入 DataSource 抽象，两种实现：
  - UrlSource：<base><file>，适用于 Pages / jsDelivr / raw 等
  - ApiSource：GitHub Contents API，只用 api.github.com
- 源顺序改为 Pages -> Contents API -> jsDelivr -> raw -> githack
- ApiSource 取内容走两条路，先 raw 再 base64：
  ① Accept: application/vnd.github.raw 直接拿原文
  ② 默认响应里 content 字段是 base64，去掉空白后解码
  实测 api.github.com 偶尔返回 504（GitHub 侧临时故障），所以两条路都留着。
- SourceProbe 增加 label 字段，设置页显示「GitHub API / api.github.com」这样
  比只显示域名好认。

关于 Pages 仍未启用：
- 已确认 GET /repos/.../pages 返回 404，即站点不存在。
- configure-pages 的 enablement: true 也失败，报
  「Create Pages site failed. Resource not accessible by integration」——
  创建 Pages 属于仓库管理操作，GITHUB_TOKEN 无权做，不是配置问题。
- 所以 Pages 需要你在 Settings -> Pages 里把 Source 选成 GitHub Actions 一次。
  README 已写明这一步，并说明不启用也没关系：Contents API 不依赖 Pages。

已验证：Contents API 端点可用（拿到 classes.json 8502 字节）。
tools/check_dart.py 四条规则全通过。
